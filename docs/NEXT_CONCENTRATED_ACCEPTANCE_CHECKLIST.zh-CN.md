# 下一次集中验收清单（未发布候选）

2026-10-26：阶段、能力差距、当前证据和案例编号以[统一账本](LOCAL_READER_DELIVERY_LEDGER.zh-CN.md)为准。本文件是交付时的用户分组步骤，不是当前候选已通过记录。两端已有用户Host选源／搜索／阅读／单章保存，Android另有明确保存的本机书目；完整Host元数据／私人标签／收藏／同步／后台恢复仍未完成。不能再沿用较早“只支持Desktop已有书库”的限制描述。

这是准备中的人工验收范围，不是已通过记录，也不是现在要求用户开始测试。先由维护者核对同一源码的完整 CI、Windows 成品、固定签名 Dev APK 与校验值，再交付一个统一验收包。未提供、未支持或未执行的项目保留待办，不能记为通过。

## 0. 先确认渠道与数据边界

- Windows 使用验收包声明的隔离程序/数据目录，以 `TEST_BUILD.txt` 和本次交付记录为准；不读取、复制或迁移正式版数据库，不覆盖正式程序。
- Android 使用 `com.picalibrary.android.dev / Pica Library Dev`。已有 Dev App 时仅覆盖安装；签名不一致就停止，不要先卸载或清数据。正式 App 与 Dev 不互相替代。
- 保留已有测试资料，先确认导入、阅读和设置仍在。敏感备份、账号、Cookie、配对码和漫画正文不上传到 GitHub 或反馈附件。
- 本轮没有修改正式 OTA。不要把软件“检查更新”返回的正式 Release 当成本候选；CI 的升级诊断夹具也不是供用户安装的更新包。实际一键升级/断电恢复验收另按明确提供的目标包和步骤进行。

## 1. 日常路径：本地书库 → 阅读 → 返回

用一份自己的小型漫画文件夹或 CBZ，先预览再确认导入。核对章节/页序、封面、阅读退出后的返回位置；同一原位置重导入应保持作品身份和进度。取消预览不应复制或改原文件。Android 导出 CBZ 只验证正文可读，不把它当作私人数据备份。

阅读时检查实际可见的阅读设置、单页/连续模式、章节切换和恢复进度；手机再检查双击/缩放/返回手势。手势、OEM、SD 卡及长期留存仍需要真机结论，不因 CI 通过自动勾选。

## 2. 来源：只连接自己需要的来源

- 既有 Pica/E-H/JM 独立验证。JM 搜索、收藏文件夹/分页、扫描预览后导入、单章下载后离线阅读分别记录；无账号或不使用该源时标“不适用”，不伪造成功。
- 自行配置兼容的 Suwayomi 2.4 Host；保存配置默认停用，启用／诊断不等于阅读许可。明确授权并选一个来源后手动搜索、详情、原Reader阅读；只测自己合法可访问的内容，不安装第三方扩展作为本次工程测试的前置。关闭面板不等于结束会话，明确“结束会话”后不能使用旧授权。
- Android“保存到本机书库”只保留书目引用。结束会话、重开App后应仍可列出／移出；未授权不能直接读，重新授权须保持同Host／账号／来源，并重新核对作品身份。“移出”只删除引用，不删本地正文、历史或Host收藏。
- 两端另有明确保存一章到本地的路径；完成后在本地书库用同一Reader离线读取。引用保存绝不能显示为正文下载完成。当前是前台有界单章复制，不承诺后台续传恢复。
- Host自身页面缓存／已配置同步可能发生。全源搜索、整个Host目录导入、Host私人标签／收藏／跨端同步和第三方扩展安装仍未完成，不列成可点击的假功能。真实官方Host＋合成LocalSource通过不等于第二个真实平台或手机真机通过。

## 3. 两个 issue 与标签方案：一次检查真实负担

分别按原始 issue 场景复现，而非只确认按钮存在：#199 是统计/语义地图的可选 BLOCK/LESS 显示过滤，来回切换后客观收藏与底层偏好不变；#200 是上游标签粗糙、真实兴趣解释不足和人工调整负担，检查低频标签检索、私人标签/映射及操作反馈，不能只凭搜索可用宣布完全解决。收藏顺序属于独立旧 Android QA，不冒充这两个 issue 的诉求；未覆盖报告场景就保留未验证，不自动关闭 issue。

标签参与范围默认全开；需要时全关并只开少量项目，先暂存再保存。分别验证手工绑定私人标签与原始标签映射，平台事实不能被覆盖，关闭参与不能解除 BLOCK。AI 往返使用导出 → 返回 JSON → 完整预览 → 明确保存 → 撤销；过期/陌生 ID 应拒绝。先用不含收藏统计和作品列表的导出检查隐私选项，不把方案名字当成无敏感信息。

确认旧推荐不会冒充已重算结果；手机离线只重排现有缓存，不冒充已经从来源召回新作品。不建立画风索引、不切 LIVE，也不重新生成冻结向量来验证标签。

## 4. 已有跨端路径：配对、LAN、WebDAV、离线

有需要再配对，区分“配对成功”与“后台同步完成”。电脑已有下载应可通过 LAN 阅读；电脑关闭后仅检查手机本地文件或实际配置好的 WebDAV，不能期望 LAN 继续可用。方案冲突按界面明确选边，不以同步完成推断长期账号秘密已复制。

本地删除与云端删除分别确认目标；这一轮不做批量删除测试。新宿主作品/标签/进度的统一跨端同步仍未提供，不能拿已有 Pica/JM 路径的成功代替它。
