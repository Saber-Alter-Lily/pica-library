## Actual gap and intended change

The persistent legacy catalogue accepts Pica/EH/JM/local identities. User-host reading already has stable principal/source/URL-owned IDs and the shared Reader, but references/progress remain separate. Unknown hosted identities correctly reject in the old catalogue; casting them as Pica is forbidden. Do not widen a string whitelist or silently import a host catalogue to hide this gap.

Implement a source-neutral **read projection** over already-owned catalogue progress and explicitly selected hosted references. Real adapters must feed a shared query/continue-reading entry point; a detached interface or synthetic test alone does not complete this phase. Keep existing data/IDs, SQL schema, source permission and Reader engines. Local and online replicas may share one work identity without merging their progress records; separate host/principal identities never merge by title. A query may neither connect/fetch nor initialize policy/cache or mutate records.

Only the browser's explicitly supplied currently authorized host session may contribute its selected references. No ambient inclusion of another host/principal/session, arbitrary GraphQL/URLs, saved credentials or whole-host fetch/import. Ending/expiring/revoking that session removes its access, not its retained state. Missing metadata is unknown, never fabricated tags/authors/progress. Corrupt optional-source state is visibly incomplete and cannot hide ordinary local records or reset data.

## Implemented local development slice

- Actual pure query/identity composition, strict bounded input, deterministic pagination, source counts, per-route progress, no title-based merge, output-copy and partial-state behavior.
- Actual legacy storage/Reader adapters use bounded bulk metadata reads and no network. Actual hosted adapter reads only matching already-selected principal-owned references and applies existing revocation guards.
- One existing Library entry point renders/resumes both paths through the existing Reader. Browser Lite and legacy full catalogue editing remain compatible; host references are not exposed to unsupported favorite/tag/recommendation/download/native/sync mutation APIs.
- Actual loopback/origin/CSRF route closure and fake-DOM UI tests, source import graph, strict TypeScript/Web syntax. Local test closure must be inspected; no whole-suite/HTTP/browser/Java/application launch.
- No database migration, mutable production data, provider protocol clone, dependency/framework or per-module updater. Keep one application update route; API compatibility must be assessed from the actual final change, not a new version number alone.

The actual Library page now has a shared, paged **Continue reading and selected books** panel, wired through the existing main Reader. It reads at most100 latest local works, the existing online history and up to500 explicitly selected host references; metadata lookup is one bounded bulk call per legacy channel. The new SQLite query selects the latest chapter per work before limiting; the old `readingProgress()` method and all stored positions remain unchanged. This is a result/metadata bound, not a worst-case database scan/performance guarantee. The legacy online100-position retention limit is unchanged; pruned historical positions are unknown, not reconstructed.

The full legacy catalogue grid/edit/filter APIs remain compatible. This panel is a common read projection, **not** generalized host catalogue import, arbitrary source registration, personal-tag/favorite/download/recommendation evidence or mobile sync. Those paths remain unsupported for hosted identities; no Pica ID coercion or inferred metadata is used. Local/online positions remain distinct routes of the same known work, and each route resumes through its existing engine. Host source facet keys are opaque hashes rather than raw principal/endpoint/credentials. Ending, expiry, permission/revision change and page exit revoke volatile authority; a plain refresh of unchanged host settings does not end or renew it. No new durable app_state key is introduced.
