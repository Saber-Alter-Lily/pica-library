# 高级功能指南

本指南按任务阅读，不需要从头配置一遍。日常找书、阅读和轻量反馈先看[日常使用入门](DAILY_USE_GUIDE.zh-CN.md)。软件内入口为 **设置 → 帮助与新手引导 → 高级功能指南**。

Web 版按七个章节定位到真实控件；Android 版提供八个离线章节，将电脑配对与 WebDAV 分开。各章节阅读状态独立，打开指南不会运行功能任务。

## 1. 账号与来源

1. 只连接需要的来源。Pica、E-H/ExH、JM 独立管理账号、权限与可用能力。
2. 检查账号身份和连接状态后，再主动同步收藏。JM 采用扫描 → 预览 → 确认 → 追加导入；部分扫描失败不能当成完整成功。
3. 收藏、Like、私人书架和下载事实不同。导入收藏不会自动变成明确的 Like 或画风偏好。

Windows E-H 的受管网页登录可以在用户完成官方页面登录后检测并验证会话。普通外部网页登录链接不自动回传会话。手动 Cookie 是高级兜底，不要公开 Cookie、密码或配对令牌。ExH 当前不可访问不等于整个 E-H 账号无效。

未发布候选增加折叠的 **基本设置 → 外部漫画来源 → 外部宿主诊断（实验）**。它只检查用户自己已运行的 Suwayomi 2.4 宿主及一页已安装来源，不会安装/启动宿主或扩展，也不会把来源启用、把目录导入书库或接通阅读。宿主不是我们运营的内容服务，更不是本地阅读的必要条件。地址、认证和本次请求范围均需自己明确确认；关闭面板停止请求并清除临时会话，不使用其他来源的凭据。实际互操作和后续 Reader/书库/手机接线仍未完成，见[边界与限制](SOURCE_HOST_INSPECTION.md)。

## 2. 推荐偏好、标签与生效范围

1. 先看“你的调整”。只有需要时再展开“查找并调整作者、IP 或标签”。画像、实际构成、策略信息与重算工具位于高级区域。
2. 搜索覆盖完整本地收藏衍生信号与已保存的调整，支持简繁体和已有别名。收藏覆盖数不是喜欢程度；未知证据不等于不喜欢。
3. 滑杆先暂存，可跨搜索保留，点击保存才写入。0 是强烈减少，不等于 BLOCK。保存后的偏好进入后续重算；当前已有批次不会因此自动成为新算结果。
4. “本次想看”和长期偏好不同。修改、清除或同步时核对范围；屏蔽偏好与屏蔽具体作品也分别管理。

当前“作为标签添加”只创建显式偏好控制，不给作品自动补标，也不建立平台原始标签到私人标签的映射。搜索同义写法不意味着它们在所有客户端、所有排序路径中已合并。

本轮未发布候选增加“用于推荐的标签与私人标签”，不要求日常使用者先配置：

- 默认全开，也可全关后只选关心的标签；只选模式中新发现的标签不会擅自加入。目录是本地已观测资料，不冒充平台全站完整目录，各分类按收藏涉及作品数排序。未知分类保留为其他，不猜测。
- 原始标签保留来源。例如 `pica|school` 与 `eh|female:schoolgirl` 不是同一个原始事实。关闭参与只停用该标签的软偏好、画像、召回和排序信号，不删除作品，不阻止作者或关联作品路线，也不解除 BLOCK。
- 手工私人标签：命名后明确绑定作品，只识别这些已标注作品。它不是可以自动识别新作品画风的模型；有可用的 Pica 作品时，只能用有来源的关联作品路线辅助召回。
- 映射私人标签：命名后选择多个带来源的原始标签，按“任一匹配”派生私人概念。私人开关独立于原始标签开关，平台元数据不被覆盖。召回只使用所映射的原始词与对应来源，绝不把私人名字或内部 ID 当搜索词。当前自动推荐没有新增 JM 在线召回接口；JM 私人绑定仍可用于已知元数据/缓存匹配。
- 修改先暂存，支持撤销。Desktop“保存方案”不重算；“保存并重新生成推荐”先保存再请求构建，旧批次保留至成功，旧标签基线会明确标记。手机保存后仅在现有候选中按当前规则重排，不冒充已重新召回；旧标签理由不继续显示。
- 标签方案参与配对同步。双方都改动时需明确选择电脑或手机的整套方案；取消、失败和同步中产生的新修改不能静默丢失。旧客户端不携带此字段时不会清空方案。

两端都不把自定义“画风”名称变成可靠的自动分类。画风参考集、向量重训及跨来源自动同义词治理仍是后续工作，本轮不更改 Visual OFF/SHADOW/LIVE 或冻结向量。

### 可选：让 AI 批量整理标签

Desktop 的标签面板可导出给 AI 的 ZIP；把 AI 填好的 JSON 导回来，先完整校验和分页预览，再确认保存。两项隐私选项默认关闭：收藏统计，以及作品列表/手工绑定。即使不开这些选项，方案和私人标签名称仍会表达兴趣，分享前自行确认。软件不自动上传，也不接受脚本、SQL 或 ZIP 导入。

不认识的 ID、过期基线或后续编辑都会阻止覆盖；可撤销最后一次文件导入，但不会回滚收藏、阅读、下载和其他设置。是否重新生成推荐单独选择。手机使用现有配对同步接收方案，本轮没有手机文件选择器。它是本机 AI 往返格式，不是长期备份或跨安装迁移文件。详见 [AI 标签方案交换](AI_TAG_PROFILE_EXCHANGE.md)。

## 3. 画风、索引与 QC

- OFF：不参与常规排序。
- SHADOW：用于分析，不改变正式排序。
- LIVE：才会让画风信号参与排序；必须按当前能力与验收状态明确启用。

先看已有索引和候选覆盖，再判断是否需要手动任务。Desktop 负责完整模型、全库向量与重任务；Android 使用同步后的轻量基础，不运行全库建模。

没有向量是未知，不是画风不相似。向量相近也不是脸型、人物属性或场景的可靠标签。自动画风分组属于分析，不应自动变成权威语义分类。已有冻结向量不能因为打开教程被重建。

Visual QC、人工评分和 Pending 诊断用于有目的的审计；不要为普通推荐问题反复点建立/补全。导出、评分、诊断与写入 embedding 的影响不同，操作前看说明。

## 4. 手机与 Desktop 配对

1. 同一 LAN 中扫码配对，手工地址与短期码是备用方式；不要公开配对码。
2. 区分配对成功和后台同步完成，查看各自状态。
3. Desktop 在线且可达时，Android 可直接读取电脑已经下载的漫画，不必再完整下载一份。
4. 手机和电脑保留独立的当前推荐周期。长期偏好、反馈、候选基础等可同步；同步不应被理解为强制两端显示同一批。冲突按界面明确处理。

配对不代表把全部长期账号秘密复制到手机，也不保证电脑关闭后所有 Provider 功能仍可用。使用独立手机会话、手机本地文件或配置好的云端副本时，按各路径要求操作。

## 5. WebDAV 与远程副本

Desktop 按 **测试连接 → 保存设置 → 扫描计划 → 检查计划 → 开始同步** 操作。Android 也需要自己的可用配置与文件。

本地、Desktop LAN、网盘是不同副本。先看哪些已上传、哪些待处理，以及任务计划的实际范围；上传本地内容不等于自动删除云端独有内容。

删除云端副本与删除本地下载必须分清目标。电脑关闭后能否从 WebDAV 阅读，取决于手机配置、网络和远程文件，而不是只看电脑以前是否配对成功。

## 6. 下载、书架与数据保护

下载失败先查来源权限、会话变化、网络和任务错误。盲目提高并发不能修复账号问题。暂停、取消和删除有不同影响；已完成文件与待恢复检查点也不应混为一谈。

私人书架只做整理。更换应用程序包应保留数据目录；正式版与隔离测试版的数据目录不能混用。不应为连接问题先清数据，也不应把测试数据库手工迁入正式目录。

Android 的本地导入文件保存在应用内部，不是可随意清掉的缓存。已导入作品的 **来源与副本 → 导出正文为 CBZ** 只保存图片与相对文件名，不包含账号、书架、阅读历史、私人标签或原始文件位置。导出期间不能移除正在使用的副本，重新导入其他版本不会切换这次导出的快照。保存失败/取消不删除外部半成品；用户应自行检查。新 CBZ 重新导入会建立新身份，**不是整套个人数据恢复**；应用卸载/清数据的完整恢复能力仍待实现。文件名和正文仍可能敏感，不会自动上传或加密。见 [模块、上限与失败语义](NATIVE_LOCAL_CONTENT_EXPORT.md)。

## 7. Shadow、评估与审计

“当前实际推荐构成”读取已经保存并实际展示的批次；V5 Shadow 规划是实验，不是该批次的真实组成。评估证据尚未成熟时表示等待数据，不是准确率为零。

运行实验前先明确目的、耗时和影响。指南只定位/解释，不自动执行 Shadow、模型、QC、身份审计或外网扫描。部分诊断仅在 Desktop 提供，手机不展示假入口。

Desktop 推荐审计导出虽排除凭据，仍可能包含目录、偏好和行为等私人信息。分享前检查内容，不把它当成天然公开数据。

## 8. 更新、维护与排障

核对版本、来源 SHA 与渠道。正式 Release、Dev、RC 及未发布包不能混为同一更新渠道。Windows 保留数据，Android 优先覆盖更新；签名不一致时停止，不为安装而先卸载丢失数据。

排障记录版本、错误原文、触发步骤和发生时间。连接问题定位到具体来源/设备；推荐问题定位到偏好与当前批次；卡顿定位到具体页面/任务。只有明确需要时才做完整扫描、重建或清理。

## 学习进度不是系统状态

章节“已读”、日常引导“完成”与账号已登录、网盘已配置、同步已结束、模型已准备是不同事实。读完教程不应显示为功能配置成功，也不会自动改变这些状态。
