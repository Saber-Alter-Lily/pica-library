## Real source code added in draft

`src/desktop/v050-historical-fixture-gate.ts` adds explicit `qualifyV050HistoricalFixtureReadOnly(sandbox)`. Its only eligible input is a uniquely marked, direct OS-temp child `pica-v050-history-qa-*` containing a synthetic `profile/` subtree. The module is **not wired** to Windows Desktop boot, updater, CLI, UI, scheduler or user profile discovery.

- Reuses original `auditLegacyDesktopProfileReadOnly` (no SQLite writes) for bounded config and DB SHA snapshots before/after.
- Distinguishes release-shaped schemaVersion=1 configuration *without* later source-policy fields. Any post-release or unrecognized fields remain **REVIEW_REQUIRED**, not auto-upgraded.
- Refuses all custom or external `libraryDirectory` references **lexically before stat/realpath/open of the target**. The production consent and independent external inventory gate is still missing.
- Stops on any instance lock, WAL/SHM/journal marker, symlinked hierarchy or untrusted/missing fixture sentinel. No lock deletion, zero-byte SQLite copying, source SDK, account login or credential-file read.
- Uses the existing Node 24.15 `node:sqlite` read-only immutable SQLite handle; never constructs `LibraryDatabase`, invokes migrations, or writes backup files.
- Requires release migration history 1–14 by version and name; checks a bounded set of 11 important original table/column sets, `PRAGMA integrity_check` and `PRAGMA foreign_key_check`. Other legitimate historic shapes conservatively enter **REVIEW_REQUIRED** instead of being silently migrated.
- Rechecks original config/DB fingerprints after SQLite close; returns only sanitized status codes, synthetic hashes and release metadata, never paths, proxy URL, cookies or credential bytes.
