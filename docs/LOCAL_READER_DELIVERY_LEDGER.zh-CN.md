## 1. 产品目标与权威规则

软件管理用户本地内容，并可连接用户自行选择的来源；不提供漫画内容、官方漫画目录、默认扩展仓库或必须登录的平台账号。阅读、书库、标签、来源、手势、推荐、同步和更新通过明确接口协作，不换框架、重建数据库或重写已有排序/Visual 算法来完成本轮。

完整链路：本地导入或自行接源 → 浏览/搜索 → 详情/章节 → 阅读/下载/离线 → 书库/历史/个人标签 → 同步与更新后继续使用。

- 本文件是阶段、验收案例和当前总状态的唯一入口；专项文档继续作为实现契约，历史日志不删除。
- 源码存在、自动验证、成品验证、真实来源、真机体验、用户接受分别记录。未执行不是通过；N/A 必须给原因，不能拿来免除已承诺能力。
- 旧源码绿灯不验证新源码；诊断夹具不是安装包；一次正常更新不证明失败恢复。
- 应用和数据分开。不得使用正式数据库、账号、G 盘程序或冻结研究资产进行自动修改测试。
- 本机不启动 Java、应用、浏览器或监听。新外部写入/构建按适用授权办理，不因本计划自动获得发布、合并或部署权限。

### P2 S2 本地推进 — Desktop 显式保存章节、会话任务与离线阅读

源码7a81e12在同一独立分支接通：浏览自选Host → **保存章节到本地…** → 列出实际章节 → 选择一章并另勾保存许可 → 确认 → 展示已读取页数/取消 → 完整保存后**本地阅读**。浏览/选章不等于保存授权，不自动添加其他作品，也不调用宿主的下载队列、收藏/进度/来源设置修改。

- 复用既有`DownloadScheduler`、下载状态机、`MediaRequestGate`/balanced请求间隔、`RuntimeResourceCoordinator`及上一段库存入口；新模块只适配当前会话任务，不复制平台下载逻辑、SQL、Reader或源协议。写入任务串行，活动任务占更新/引擎切换保护；引擎关闭等待任务退出后再关数据库。平台旧下载表会建立待取元数据条目/行为事件，故不让它误领Host任务，不改schema或旧表调度。
- 初始阅读/搜索许可不隐含保存，须额外`consent + acceptLocalCopy`；只能保存该会话实际选到的章节。任务最多20个未完成/50条临时记录，使用会话认证和已有15分钟期限；结束、禁用、过期或退出取消未完成任务，重启不恢复网络。完成副本是独立本地内容，不随撤销删除；失败可重新明确确认保存，不自动重试。沿用既有单页20MiB、全书2000页/512MiB库存限制，不声称无限容量。
- 状态/取消只读取本会话任务，不联系Host；不持久化任务、凭据或远端URL。并发重复提交复用活动任务，完成后重新确认可以更新副本；保存失败保留原副本、收藏和进度。取消在原子提交之前阻止发布；若提交已完成，仍报告已保存而不把健康副本误报为已取消。保存进度明确是已读取页数，未完成不冒充完整离线书。
- 最终`regression-3`为**453PASS/0FAIL/0skip，31文件**，其中新增服务17项、实际UI模块惰性DOM8项；`types-4`完整类型及`web-4`的54/54模块语法通过，12轮离线边界审计0事件。真实临时SQLite/PNG/Reader与资源协调器覆盖断源重开、取消/撤销/过期、排队资源取消、限量、重复/跨会话、失败重试、替换保留、晚到取消及模块依赖边界。4项原始UI失败保留，均是新夹具将`copy(zh,en,ja)`的中英文序号写反；修夹具而非产品语言或安全校验。

**出口仍未收缩**：当前任务在Host面板可见，下一步补同一任务在统一下载入口的有界投影，以及Android来源/阅读/离线接入；再由同源码成品/真实Host验证SRC-05/06。不能把本段Desktop工程路径当作P2、手机离线或完整产品完成。

## 6. 模块与数据约束

复用现有 Library API2、Tags API2、来源能力契约、媒体传输和 Reader 端口，保留应用适配器。来源不拥有本地文件删除/更新权限；标签不拥有原始平台事实；推荐不拥有登录状态；同步不默认复制凭据；模块可演进但对用户仍是一个应用更新入口。

标签关闭只约束相应标签信号。作者/分类/关联/画风须作为独立开关或解释，不宣称它们也已关闭。人工绑定只认识已绑定作品，不是未见作品分类器。AI 交换当前为 Desktop/Web 导出和返回 JSON；Android 经已确认规则同步使用，不声称已有手机文件选择器。

需要保护的对象包括：收藏、阅读进度、书架、原始元数据、私人标签/映射、偏好、反馈、行为/Shadow、Visual 向量与模式、同步队列/配对、下载文件和账号秘密。更新比较逻辑状态及文件身份，不能错误要求正常阅读写进度后数据库字节仍完全一致。自动变更验证仅用合成隔离资料。

## 7. 防循环和下一动作

1. 一个总账本、一个应用基线。未完成阶段不增添任意新功能/格式/来源/模型，也不为每个小修新发 Dev 包。
2. 每项代码改动必须对应上面的案例和实际缺口；纯模块拆分不能代替用户链路交付。
3. 同一失败最多两轮有证据的修复，然后提交路线/依赖评审。产品、测试、基础设施和上游错误分别记录，不把不同根因混算，也不清除旧失败。
4. 先做最小相关验证，再做冻结源码的完整门禁；不原样反复重跑，不放宽安全/时间/恢复门禁换绿灯。
5. 用户不逐阶段陪跑。维护者先完成工程项，再一次交付日常/高级两组步骤，已通过且未受影响的项目不反复重验。
