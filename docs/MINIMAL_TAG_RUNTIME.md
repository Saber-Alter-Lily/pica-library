# Minimal tag rules versus historical review evidence (NEXT-65, unpublished)

## Product boundary

Pica Library is a reader and personal library, not a manga platform. A frozen tag/entity/alias vocabulary is not an app-operated catalogue or content source. Historical review tables containing example titles/authors, provider prevalence, favorite/catalog counts and review notes must not be copied into installable runtime merely because some semantic columns are needed. User profiles, credentials, bodies, vectors and private-tag policies are outside this build projection and are never inputs.

The old `src/data/registry-v3-final` authority is retained in tracked source for provenance/replay. It is **not staged into application packages**. Removing evidence fields does not establish the historical vocabulary's licensing/provenance or finish source-neutral core separation; historical fixed Pica/EH/JM adapters/UI and optional source-owned vocabulary remain open.

## Actual module and reuse

- `src/tag-assets/registry-v3.ts` is the application asset/legacy compatibility adapter, with no recommendation/provider/account/database/sync imports. It reuses the existing CSV parser, adapters, key precedence, aliases and open-world/safety behavior. `recommendation-v3/tag-resolution-v3.ts` retains the exact frozen resolution body and re-exports compatibility types/loader/parser.
- `runtime-format.ts` defines a versioned seven-file allowlist, strict metadata/column/alias shapes and bounded regular-file UTF8/hash reads. No new dependency, taxonomy engine, compression format, model or plugin framework.
- `scripts/build-tag-runtime.ts` mechanically projects only consumed columns/alias fields from the frozen tracked authority. `--check` compares exact generated bytes. It refuses unknown output files, does not delete old research or access a library/profile, and is not a user taxonomy editor.
- `scripts/stage-tag-runtime.ts` is shared by Windows x64/ARM64, Linux and macOS packagers. It verifies and copies only the seven assets to `app/runtime-assets/tag-runtime-v1`, refuses a pre-existing/mixed legacy application stage and checks the result. No directory-wide evidence glob or source-compatible duplicate.
- Staging requires real engine/module-contract file markers, not merely an existing directory. macOS uses Contents/Resources, not the outer archive root; obsolete src symlinks are not retained. The first pushed macOS build failed when these roots were confused; exact root/counterexample checks and raw failed CI are retained before fresh validation.

Files: `TAG_RUNTIME_MANIFEST.json`, `semantic-v2.csv`, `semantic-v3.csv`, `entities-v3.csv`, `unresolved-v3.csv`, `aliases-v2.json`, `aliases-v3.json`. Total generated bytes: 82455 at the frozen authority. No example titles/authors, corpus statistics, context/review columns or unused reviewed/final CSV are part of this schema.

The V2 legacy parser retains a BOM-prefixed first header and never reads its raw_tag as a normal key. The new V2 projection omits that unused raw column; it does not silently repair the parser or add new lookup keys. Full map equality and frozen-implementation differential tests guard the exact behavior, including malformed historical spellings.

## One update action; no unsafe incremental deletion

Moving from an old full package with `src/data/registry-v3-final` requires **the existing one-click full application replacement**. Those old source-path deletions are outside the incremental allowlist. The builder must reject the unsafe incremental package, not weaken path safety or leave historical evidence behind. A future authorized release must offer the verified full archive for that transition; the existing UpdateManager reports the full-only release as oneClick=true. No stable release/OTA is created here.

Once both ends use the new app-only layout, valid semantic-identical transport updates remain on the normal `app/` incremental path. A mixed target with both minimal rules and the old review tree is refused. No updater helper, global/module API, database schema, user path, preference or sync format is changed.

The compiled Windows full-update matrix is extended to compare exact original asset bytes after either rollback, and exact clean candidate assets after successful replacement, including absence of both old review roots. The existing external config/SQLite/deep-path canaries remain. These are **CI-only fixtures**, not proof of physical power-loss/UNC/old-controller OTA behavior or a deployment on the user's computer.
