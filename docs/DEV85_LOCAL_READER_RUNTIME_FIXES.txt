Problem -> implementation
-------------------------
1. Stored page survived restart, but continuous Reader displayed page one.
   The old viewport adapter positioned lazy images after two animation frames without waiting for loaded geometry, then accepted observer-driven page changes. Its old tests mocked scrollIntoView without cold layout behavior.
   The adapter now waits for the saved image to be ready, requests only that image eagerly, repositions on preceding-image load/ResizeObserver changes, and does not replace the saved page from layout-only callbacks before real scroll/navigation intent. CSS reserves a lazy-page box. Exit/chapter/mode ownership still fences delayed work. A synthetic geometry model checks actual computed page centering, not only a scroll spy. This remains a simulated geometry test, not a new real-browser PASS.

2. Mode/direction/fit reset on document reload.
   A small runtime-neutral versioned codec rejects unknown/invalid fields. Desktop saves only these display preferences to its existing non-secret profile config; ordinary settings edits retain them, with no DB migration. Web applies the profile after bootstrap, caches display settings locally for Browser Lite, serializes rapid edits and refuses stale status overwrites while edits are pending or Reader is active. Save failure is visible. No book identities, page positions or credentials enter this setting.

3. Interactive Desktop opened LAN Mobile Bridge without a connection choice.
   Absent/legacy config is now off. Settings -> connection offers an explicit enable confirmation and disable button, separate from manga source login/enablement. A successful opt-in can persist for later interactive starts. Existing paired-device records are kept; enabling does not clear or regenerate them. Disabling closes the current listener even if saving the choice fails; such failure is reported rather than claimed durable. A failed close remains visible and retryable. In-flight activation cannot survive shutdown ownership changes.
   Headless still additionally requires --mobile-bridge. Saved explicit off takes precedence over the fallback startup flag. Upgrading an older auto-on installation requires the user to explicitly enable LAN sharing once; finding an old state/pairing file is not treated as consent.
